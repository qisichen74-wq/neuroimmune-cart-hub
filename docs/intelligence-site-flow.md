# 情报网站当前流程与前后台职责

更新日期：2026-08-21

## 1. 当前流程

1. 自动发现  
   来源包括 PubMed、ClinicalTrials.gov、CDE 中国药物临床试验登记平台、重点企业官网与监管入口。脚本只负责抓取、去重、初筛与生成候选，不直接把线索写入正式数据集。

2. Hermes 候选分流
   研究文献、官网更新与交易线索进入候选池后，由 Hermes 按来源等级、去重结果、字段完整度和纳入规则自动分级。临床试验保留为“试验登记”线索；异常、冲突或低置信度对象进入告警队列，不进入公开数据。

3. 自动处置
   Hermes 对候选执行发布、持续观察或排除三种决定。每次处置写入可追溯记录，保留规则版本、时间、理由、字段差异与来源证据；线索不会因自动发现而直接成为事实。

4. 正式收录  
   只有通过一手来源字段核验、结构审计且无阻断异常的对象，才进入正式数据集、关系网络、专题聚合、交易时间线和详情页。

5. 审计发布  
   每次本地启动与发布前，统一执行数据审计，检查结构完整性、交叉引用、来源登记、来源确认时效与内部页面资源。

## 2. 前台页面分工

- `index.html`
  展示正式收录后的总体概览与每日重点，不展示未处理候选作为既成事实。

- `deals.html` / `deal.html` / `company.html`
  展示经核验的并购、融资、许可与制造交易，以及关联公司、项目、金额口径和一手来源。

- `radar.html`
  展示官网监测覆盖、变化信号与待继续跟进项。页面强调“变化信号 ≠ 正式结论”。

- `detail.html`
  展示正式数据对象的结构化档案、来源状态、关联关系与最近动态。

- `quality.html`
  展示来源确认覆盖、审计告警、来源登记与复核周期，不把内部判断伪装成外部事实。

## 3. 后台流程职责

- 自动发现层只生成候选与来源快照。
- Hermes 层负责字段核验、置信度、冲突检测和处置记录。
- 数据审计层负责结构、引用、日期、金额语义、来源登记和公开白名单检查。
- 公开构建只复制明确列入白名单的页面与数据；登录、候选、告警和决策日志不进入生产目录。

## 4. 数据语义边界

- `待处理`
  代表候选已进入处理台，但尚未形成闭环处置。

- `试验登记`
  代表临床试验作为登记线索保留，不进入处理台逐条确认。

- `已收录`
  代表对象已进入正式数据集。

- `来源已确认`
  代表字段已完成一手来源逐字段确认。

## 5. 本次架构调整

- 取消公开站人工审核与内部登录入口，Hermes 负责候选自动核验和异常分流。
- 新增组织、项目、交易、交易节点四类稳定实体及 JSON Schema。
- 金额严格区分已支付或已到账、潜在总额、或有金额和未披露。
- 新增资本与交易总览、交易详情、公司详情、首页交易摘要和全局搜索入口。
- 生产构建从内部黑名单改为公开白名单，并生成文件哈希发布清单。
